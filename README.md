# Классификатор обращений

Сервис разбирает входящие обращения с помощью ИИ: относит каждое к одной из заранее заданных
категорий и готовит черновик ответа на русском. Категории хранятся в базе и меняются
в интерфейсе без правки кода. Есть веб-интерфейс оператора, REST API и CLI, который делает
ровно то, что просит задание, — печатает категорию и черновик для каждого обращения
из `messages.txt`.

## Запуск

```bash
git clone https://github.com/BAITC-Hacks/hack-160aab26-aiai.git
cd hack-160aab26-aiai
./start.sh
```

Одна команда делает всё:

1. При первом запуске спрашивает ключ LLM (ввод скрыт), адрес API и модель, пишет их в `.env`.
   Подойдёт ключ любого OpenAI-совместимого API: OpenAI, LiteLLM, OpenRouter.
   Пустой ввод — запуск без ИИ, на запасных правилах.
2. Собирает и поднимает контейнер (`docker compose`), ждёт healthcheck. База SQLite создаётся
   и заполняется тремя категориями сама.
3. Прогоняет `messages.txt` и печатает результат в терминал.
4. Сообщает адрес интерфейса: <http://localhost:8000>.

Нет Docker — тот же скрипт сам поднимет сервис локально через `venv` (нужен Python 3.10+);
принудительно: `./start.sh --local`. Остановить контейнер: `./start.sh stop`.

На Windows без WSL: скопируйте `.env.example` в `.env`, впишите ключ
и выполните `docker compose up -d --build`.

## Что получилось

Живой прогон пяти обращений из задания (модель `gpt-5-mini`, все пять разбираются параллельно
за ~9 секунд):

| № | Обращение | Категория | Уверенность |
|---|---|---|---|
| 1 | Как получить справку о месте учёбы? | справка | 95% |
| 2 | В столовой очередь, еда холодная. | жалоба | 95% |
| 3 | Хочу записаться на консультацию завтра. | другое | 90% |
| 4 | Пропал Wi‑Fi в корпусе B. | жалоба | 92% |
| 5 | Где парковка для гостей? | справка | 92% |

«Справку» мы трактуем как информационный вопрос, поэтому туда попадает и парковка;
запись на консультацию — просьба, а не вопрос и не жалоба, поэтому «другое».

Модель не знает внутренних фактов организации (кабинеты, телефоны, сроки), и промпт запрещает
их выдумывать — поэтому черновики отправляют человека в нужную службу или просят уточнить.
Это черновики: оператор проверяет и правит их перед отправкой.

## Как это работает

- **Один вызов LLM на обращение.** Системный промпт собирается из активных категорий:
  название, описание «когда выбирать» и подсказка «как отвечать». Модель возвращает JSON:
  категория, уверенность, обоснование, черновик.
- **Ответ модели проверяется.** Нет JSON, пустой черновик, сбой сети — одна повторная попытка.
  Категория вне списка — обращение уходит в категорию по умолчанию («другое») с уверенностью
  не выше 50%. Завести несуществующую категорию модель не может.
- **Запасной режим.** Если ключа нет или LLM не отвечает, работает классификатор на ключевых
  словах с шаблонным ответом. Такой результат помечен `engine: rules`, причина отказа LLM
  записана в пояснение. Пять обращений из задания он разбирает так же.
- **Текст обращения — данные.** Он передаётся отдельным сообщением, а промпт запрещает
  выполнять инструкции из него.
- **Всё хранится в SQLite**: обращения, результат разбора, правки оператора.

Подробнее о решениях — в [docs/design.md](docs/design.md).

## Интерфейс

- **Обращения**: форма нового обращения (Ctrl+Enter), кнопка «Прогнать примеры
  из messages.txt», карточка результата с категорией, уверенностью и обоснованием.
  Оператор может сменить категорию, отредактировать черновик, скопировать его и отметить
  обращение отвеченным. История фильтруется по категориям.
- **Категории**: добавление, правка и удаление. Изменения действуют со следующего обращения.
  Прошлые обращения удалённой категории сохраняются.

## CLI и API

```bash
python -m app.cli messages.txt             # категория и черновик для каждой строки файла
python -m app.cli messages.txt --offline   # без LLM, на правилах
python -m app.cli свой_файл.txt --no-save  # не записывать результат в базу
```

В Docker: `docker compose exec app python -m app.cli messages.txt`.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/classify` | разобрать одно обращение: `{"text": "..."}` |
| `POST` | `/api/batch` | разобрать пачку до 50 штук: `{"texts": ["...", "..."]}` |
| `GET` | `/api/tickets` | история; фильтры `category_id`, `status` |
| `PATCH` | `/api/tickets/{id}` | итоговый ответ, статус, исправленная категория |
| `GET` `POST` | `/api/categories` | список и создание категорий |
| `PUT` `DELETE` | `/api/categories/{id}` | правка и удаление категории |
| `GET` | `/api/stats`, `/api/health` | счётчики и состояние сервиса |

Интерактивная документация — <http://localhost:8000/docs>.

```bash
curl -s localhost:8000/api/classify -H 'Content-Type: application/json' \
  -d '{"text": "Пропал Wi-Fi в корпусе B."}'
```

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_API_KEY` | пусто | ключ API; без него работает запасной режим на правилах |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | адрес OpenAI-совместимого API |
| `LLM_MODEL` | `gpt-5-mini` | модель |
| `LLM_REASONING_EFFORT` | пусто | `minimal` / `low` / … — ускоряет reasoning-модели |
| `ORG_NAME` | `учебное заведение` | от чьего имени готовятся ответы, попадает в промпт |
| `PORT` | `8000` | порт интерфейса |

`.env` в `.gitignore` и создаётся с правами `600`: ключ не попадает в репозиторий.

## Тесты

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

76 тестов, LLM в них заменена фейком: разбор и проверка ответов модели, повторные попытки
и откат на правила, API, CLI, база. В `.github/workflows/ci.yml` настроен workflow
GitHub Actions: тесты и сборка контейнера с проверкой healthcheck.

## Структура

```text
app/
  classifier.py   промпт, проверка ответа LLM, повтор, откат на правила
  llm.py          клиент OpenAI-совместимого API
  rules.py        запасной классификатор на ключевых словах
  db.py           SQLite: категории, обращения, счётчики
  main.py         FastAPI: REST API и раздача интерфейса
  cli.py          разбор файла с обращениями
  static/         веб-интерфейс, один HTML без сборки
tests/            pytest
messages.txt      пять обращений из задания
start.sh          запуск одной командой
```

## Ограничения

Авторизации нет: сервис рассчитан на внутреннюю сеть, наружу его нужно ставить
за авторизующий прокси. Ответы никуда не отправляются — оператор копирует готовый текст
в свой канал связи.
