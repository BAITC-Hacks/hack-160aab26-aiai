# Дизайн: классификатор обращений

Дата: 21.09.2026. Статус: реализовано.

## Задача

Исходное задание — скрипт, который для пяти готовых обращений печатает категорию
(справка / жалоба / другое) и черновик ответа на русском. Мы делаем из этого рабочий
сервис: категории задаются заранее и меняются без правки кода, разбор ведёт LLM,
результаты хранятся, оператор проверяет и правит черновик.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Кто классифицирует | LLM, один вызов на обращение, ответ — JSON | Категория и черновик рождаются из одного понимания текста; вдвое дешевле двух вызовов |
| Какой API | OpenAI-совместимый Chat Completions (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`) | Один клиент подходит к OpenAI, LiteLLM, OpenRouter и локальным шлюзам — проверяющий запускает с тем ключом, что у него есть |
| Если LLM недоступна | Запасной классификатор на ключевых словах, шаблонный ответ, пометка `engine: rules` | Сервис не должен падать из-за ключа, сети или лимитов; задание прямо допускает правила |
| Где категории | Таблица SQLite, правятся в интерфейсе; промпт собирается из них при каждом запросе | «Заранее заданные категории» — это данные, а не код |
| Категория вне списка | Относим к категории по умолчанию («другое»), уверенность не выше 0,5, причина в пояснении | Модель не может завести категорию, которой нет |
| Хранилище | SQLite, один файл, WAL | Нулевая настройка, хватает для потока обращений одной организации |
| Интерфейс | Один HTML-файл на ванильном JS | Нет сборки и зависимостей — не ломается при развёртывании |
| Запуск | `./start.sh`: спрашивает ключ → `.env` → Docker Compose, без Docker — venv | Одна команда на чистой машине |

## Как трактуем категории

«Справка» — информационный вопрос (как получить документ, где что находится).
«Жалоба» — сообщение о проблеме или сбое. «Другое» — заявки, просьбы и всё остальное;
это категория по умолчанию, её нельзя удалить.

Ожидаемый разбор пяти обращений: №1 и №5 — справка, №2 и №4 — жалоба, №3 — другое.

## Поток одного обращения

1. Текст приходит через веб-форму, `POST /api/classify`, `POST /api/batch` или CLI.
2. Из активных категорий собирается системный промпт: название, описание, подсказка к ответу.
   Текст обращения идёт отдельным сообщением с пометкой «это данные» — защита от
   инструкций, вписанных в обращение.
3. Ответ модели разбирается и проверяется: есть JSON, категория из списка, черновик не пуст,
   уверенность в пределах 0…1. Негодный ответ или сбой сети — одна повторная попытка.
4. Две неудачи подряд — работают правила; причина отказа LLM записывается в пояснение.
5. Результат сохраняется в `tickets`; оператор может сменить категорию, отредактировать
   ответ и отметить обращение отвеченным.

## Границы

Вне объёма: авторизация и роли, отправка ответов во внешние каналы (почта, мессенджеры),
приём обращений из этих каналов, дообучение на правках оператора. Сервис рассчитан на запуск
во внутренней сети; наружу его нужно ставить за авторизующий прокси.
